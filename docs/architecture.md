# How AI Collab works

`src/main/cli.mjs` locates the CLIs, checks their login status, starts isolated child processes, parses their JSON streams, and terminates process groups on cancellation. Public assistant text is displayed; private reasoning events are excluded.

`src/main/orchestrator.mjs` owns the conversation and its question history. Each question begins with a moderator clarification check, then knowledge checks and any web research they request (below), followed by a moderator planning call that produces a refined question and two distinct role assignments. The moderator is a separate logical participant using the Codex transport and an explicit model, defaulting to `gpt-6-sol`; it does not require a third login.

Clarification asks only for decision-changing information the user can supply, using the question, source text, and previous conversation. Up to three questions offer suggested options and free-text answers. A required clarification is persisted as `awaiting_input`, releases active provider work, and retains the remaining question time budget. Human waiting time does not use that budget. Answering resumes the same turn after authentication/model revalidation; duplicate or stale submissions are rejected. Explicitly choosing to proceed with assumptions is recorded as such. Pending questions survive restart, can be stopped, and are included with their answers in subsequent context and Markdown export.

Moderator clarification, planning, and judgment use Codex's [schema-constrained output](https://learn.chatgpt.com/docs/non-interactive-mode#create-structured-outputs-with-a-schema). The adapter writes a private temporary schema, reads the final response separately from any progress messages, and removes the schema after the call. App validation still checks question IDs, distinct perspectives, candidate versions, and review validity. A repair attempt receives the specific validation problem; invalid responses never become plans or approvals.

Before planning, each debater runs a knowledge check that returns JSON listing anything the question depends on that it does not reliably know. A debater that flags something makes one research call with only its provider's hosted web search enabled (Codex `web_search="live"`, Claude `--tools WebSearch`); every other tool stays disabled. That call receives the question, current clarification answers, and flagged items, never the attached documents or full transcript. Its brief joins the public conversation, so the moderator and both debaters see it. Knowledge checks are not shown in the transcript, an unreadable check requests no research, and a failed search is recorded without stopping the question.

Codex proposes an answer, Claude responds, and Codex prepares the first candidate. Both debaters independently review that exact candidate version, then the moderator adjudicates it. Successive revisions alternate between the debaters and require fresh reviews and judgment. Valid moderator finalization ends the question; consensus is recorded only when both reviews also approve the exact finalized draft. Invalid or mismatched structured responses cannot establish approval or a decision. Interrupted drafts retain explicit review and approval status.

Follow-ups reuse the same conversation ID and append a new question and moderator plan. Discussion, clarification, and judgment calls receive the accumulated public conversation and source text. Web research receives only the question, current clarification answers, and flagged lookup items; presentation summaries receive only the original response being summarized. The app keeps earlier plans, roles, and answers intact and records the models and outcome for each question.

`src/main/summaries.mjs` produces short display summaries of substantive messages using GPT-6 Sol over the Codex transport. A bounded JSON schema and local validation produce a headline and up to three short points. The original message remains the authority for context, exact-version reviews, final answers, copying the full response, and exports. Summaries neither establish agreement nor replace candidate text. They have a short timeout within the shared question budget and fall back to the original response on failure; cancellation still propagates. This adds Codex usage, but no new account or credential path.

`src/main/models.mjs` discovers model choices through the installed CLIs and caches the catalog. `src/main/attachments.mjs` validates and stores imported documents. macOS PDF extraction and OCR use a bundled native helper. Windows PDF text, DOCX, and RTF extraction run in a bounded worker. Excel is also parsed in a worker with resource limits. Extracted documents are supplied as quoted source material to both assistants throughout the debate.

`src/main/main.mjs` owns the native window, local history, exports, and a narrow IPC bridge. The renderer is sandboxed with Node integration off and a restrictive content security policy. Model responses are rendered as text with a small Markdown formatter; raw HTML is never executed.

The renderer lives in `src/renderer/`. It presents distinct speaker cards, compact moderator events, paired reviews, a phase overview, and an inline clarification form. Original responses remain expandable and the final answer remains complete. There is no frontend build step and no remote CDN dependency.
